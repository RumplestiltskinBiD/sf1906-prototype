**Объём:** аудит и план, не реализация механики. Старт по прямой команде автора. Проверенная база main: `975bf11d61ed609346a19b09e0173130846cbe7b`, игра v0.54.1; редактор композиции PR #246 объединён после успешного [Prototype QA](https://github.com/RumplestiltskinBiD/sf1906-prototype/actions/runs/45428650199). ## 3. Контракт геометрии и координат

- Чистый общий модуль геометрии (предлагаемое имя `physical-map-geometry.js`); единый версионированный реестр (например `map-layouts.js`). Имена файлов рабочие, а не существующие файлы. Данные формы, физического размера, угла, посадочного допуска, линий сгибов отделены от состояния.
- Канонический ID `districtId-ordinal`, ordinal начинается с 1. 21 район, 18 строительных, 79 ID: marina=2, northbeach=3, chinatown=2, innerrichmond=4, innersunset=3, sunset=6, bernal=4, остальные 11 по 5; presidio/park/twinpeaks=0. Никаких автоматических переименований при изменении картинки. Связность остаётся из core.
- Legacy JSON v1: x/y — верхний левый угол *опорного квадрата* 40 мм в исходном SVG, не размер гекса. `u = 1536 / boardWidthMm * 100 / magnification` SVG-единиц/мм; центр в слое `(x+20u, y+20u)`, перевод в корневой SVG один раз: y−11. При неизменной рамке исходный HEX50 точно воспроизводится. Для будущего канонического реестра хранить явные центры, конвертировать legacy однократно, обратимость проверять. При правке ширины/масштаба явно различать сохранение legacy-координат и фиксированного центра; не сдвигать участки скрытно. CSS-zoom не меняет мм или экспорт.
- Правильный гекс D между вершинами; apothem=D√3/4. Посадочный допуск c **перпендикулярно каждой грани**: D_hole=D+4c/√3, не D+2c. Отверстие всегда правильное, срез только на тайле. Срез a вдоль двух соседних граней: хорда a√3, глубина a/2. Проверять диапазон a относительно стороны D/2. Угол слота и ориентация владельца независимы: angle + 60°×seatIndex. Проверить также зеркальное двустороннее оформление; физический переворот может потребовать поворота, но владелец не меняется. Размер/форма цветовых меток должны оставлять 5 остальных скрытыми при всех допусках, в том числе боковом люфте; цвет дублировать символом/паттерном как кандидат.
- Различать зазор тайл–тайл, зазор отверстие–отверстие, край, сгиб, логистику и район. Технологическая проверка на реальных многоугольниках отверстий (не только bbox); выдавать пары ID и расстояния. Отдельная визуальная диагностика границы района — не новая игровая проверка. Не блокировать свободные эксперименты и экспорт проблемной карты; явно отмечать, что не годится к печати.
- Сгибы задаются в мм рамки, сетка 2×2/3×2/4×2/4×3 и отдельный режим защиты. Модель различает гибкий шарнир и разрез, верхние накладки не пересекают стык. Номинальные габариты сложенной стопки не являются расчётом заводского шарнира. Пропускать в производство только после шаблона и образца.

## 4. Контракт игрового состояния

- `mapVersion` независимо от существующей версии сохранения: рабочие ключи `legacy-90` и `hex-79-v1`. Пока не меняем default. Новый запуск переключается только на этапах 9–13 после проверки. При отсутствии mapVersion в валидной старой партии считать legacy-90; не переселять автоматически, сохранять исходные C#, объекты, деньги, прогресс, заказы, материалы. Для новой карты один неизменяемый реестр лимитов; `state.districts[id].sites` при необходимости остаётся совместимой проекцией, нормализуемой из версии, не независимым источником. Не затрагивать landValue.
- Только `state.constructions[]` авторитетен для занятости. В новой партии каждый активный объект имеет ровно один существующий slotId того же districtId; не более одного активного объекта на слот. У abandoned/redeveloped slotId сохраняется как история, свободный участок может использоваться снова. Статусы будущей катастрофы не считать автоматически свободными. Legacy не требует slotId, использует прежнее отображение. Не создавать массив занятых мест, который может разойтись с constructions.
- `constructionEligibility(...,{redevelopId,slotId})` проверяет существование, район, занятость, валидную замену и все старые условия. В hex-79-v1 реальное начало получает конкретный слот; для районного предпросмотра допускается eligibility без выбора, но commit без slotId запрещён. При невалидном слоте никаких изменений state. Старые вызовы и тесты legacy сохраняются; тестовые сценарии hex явно указывают версию.
- При перестройке новый C# наследует slotId, при реорганизации тот же C# сохраняет слот. Доставка, действия, доход, исследования, пожарная/медицинская защита, цели, запасы, ownership и связи продолжают обращаться к C# и districtId. Ни геометрический сдвиг, ни поворот тайла не являются игровым действием.
- Новая версия при загрузке валидируется на дубли, неизвестные ID, несовпадение района и лимита. Не пытаться молча «исправить» конфликтный сейв и не терять его при ошибке; предусмотреть явную диагностику/сохранение исходного снимка. Повторная загрузка и Undo идемпотентны. Строго отличать текущий формат данных от версии печатной графики.

## 5. Общий рендерер и P22

Точки расширения: (1) новый размер/раскладка/складывание — новая версия геометрического реестра без правок движка действий; (2) новый проект/товар — семантический описатель из каталога и общий шаблон тайла, не новая ветка доставки; (3) будущая Фаза II — явная модель разрушения поверх C#/slotId, без смены ID.

- Чистая модель представления: идентификаторы, сторона (under/complete), категории, требования/рецепт/поставленные материалы, условный/фиксированный Income, VP, У/П, действие и его занятость, запасы/лимиты/уникальный текст. Семантические поля и явные описатели, не парсить произвольный effect регулярками. Общее SVG-представление для обеих страниц; адаптер демо отдельно от адаптера core. Рендерер не меняет state, не рассчитывает экономику.
- Лаборатория сохраняет геометрию и отдельно демо-состояние, импорт v1 совместим (включая boardFrame PR #246). Нельзя переносить placeProject/supplyMaterial в игру. Реальные проверки доставки, R02, налогов и выплат остаются в core.
- Физические зоны проверять на 5 кубиках склада и рабочем ~14×9 мм, при всех поворотах и обеих сторонах. Не обещать читаемость 40 мм без теста 1:1. Базовая конструкция без дополнительной пальцевой выемки; запасной вариант обсуждается только при провале физического теста. Не менять назначение Офиса и не вводить дубликаты именных карточек.
