# R01–R08 — аудит этапа 0 и границы этапа 1 (19.11.2026)

**Основание:** `main` 8811a7b20471336781142006aa23071e57f1089b; [план этапов 0–10](RESEARCH_IMPLEMENTATION_PLAN_2026-11-19.md); [issue #207](https://github.com/RumplestiltskinBiD/sf1906-prototype/issues/207). **Статус:** аудит и изолированная основа state в отдельной ветке; не утверждение об активной механике исследований.

## Инварианты для всех этапов

- Три игрока, три представителя на игрока и три годовых слота активации; исследование из Civic Center/кампуса забирается **основным действием**, оплата — **быстрым** действием. Нельзя обходить `canTakeMainAction`, `consumeMainAction`, `canUseFreeAction` или логику хода.
- Только **один реестр статуса** на каждую уникальную R-карту; никакого дополнительного рынка/колоды исследования, лимита неоплаченных карт или автоматического ежегодного сброса.
- Каждая завершённая копия здания с размещением работника занята один раз в год через **общую** `actionSpaceOccupancy`. Текущая кодовая проверка реализована поимённо у некоторых зданий: банков, бюро, магазина, пожарной части, дворца правосудия, пансиона, клуба и агентства. Прежде чем включать кампус, требуется полная проверка оставшихся действий, правильный сброс при переходе года и reload.
- Действующие `PROJECTS`, `STANDARD_PROJECTS`, `research-cards.js`, география, реальная погрузка и цены, генератор газет и `catastrophe-core.js` остаются источниками истины; если эффект затрагивает их, меняем конкретный общий обработчик, а не дублируем алгоритм в UI.
- Миграция `app.js::migrateState` обязана сохранять все карты/стройки/деньги/работников/год/газету из прошлых save. `createInitialState` не должен тратить дополнительные вызовы RNG.
- Реальная интеграция в `main` допускается лишь с положительным/отрицательным/граничным/старосохранённым тестом и браузерным проходом в 390×844 и 932×430 на финальном HEAD. Не путать эмуляцию Playwright с тестом физического телефона.

## Архитектура состояния (этап 1)

`research-state.js` опирается на **единственный каталог** `RESEARCH_CARDS` и инициализирует `state.research[id]`:

- `{status:'available',holderId:null,fundedRound:null}`;
- `{status:'held',holderId:<playerId>,fundedRound:null}`;
- `{status:'funded',holderId:<playerId>,fundedRound:<round>}`.

Здесь `holderId` у профинансированной карты — идентификатор спонсора; отдельного дублирующего `sponsorId` нет. Валидация диагностирует невалидные записи **без повреждения существующего save**. `ensureResearchState` добавляет недостающие ID и сохраняет старые записи и неизвестные ID для совместимости; не выполняет действие/платёж. API селекторов возвращает копии, а не внутренний изменяемый объект.

**Проверка P22:** если одобрят R09, добавление записи в `research-cards.js` автоматически создаст отсутствующий слот новой партии и старого сохранения; существующие UI и хранилище исследований не должны требовать отдельного жёсткого списка. Само исполнение нового типа эффекта потребует только профильного обработчика в соответствующей общей точке, не второго движка исследований.

## Что пока НЕ реализовано

Этот этап не предоставляет карт игрокам, не проверяет стоимость, не включает общие эффекты, не открывает кнопку кампуса и не меняет условия действия Civic Center. Отдельный следующий этап должен внедрять универсальную транзакцию получения с реальным рабочим; ещё следующий — финансирование. R05 и R08 сохраняют перечисленные вопросы дизайна/интеграции из master plan; нельзя выдавать заложенный state за их устранение.

Известные другие открытые PR: #142 (исторический документ) и #16 (устаревший черновик газет); к реализации исследований отношения не имеют. Issue #207 остаётся открытой.
